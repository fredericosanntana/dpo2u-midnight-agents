# Architecture

## Overview

DPO2U Midnight Agents operates across two chains:

1. **Base Chain (EVM)** — Solidity smart contracts handling token economics, treasury management, and agent registration via ERC-8004
2. **Midnight Network (ZK)** — Compact contracts enabling privacy-preserving agent operations, fee distribution, and compliance

## Dual-Chain Design

### Why Two Chains?

- **Base Chain**: Public agent identities, transparent treasury, token economics visible to market
- **Midnight**: Private operations — how much each agent earns, compliance data, wallet balances hidden via ZK proofs

This separation means agents have **public accountability** (ERC-8004 reputation on Base) with **private operations** (ZK-shielded transactions on Midnight).

## Component Map

### Solidity Layer (Base Chain)

```
DPO2UToken ──fee──► Treasury ──withdraw──► Agent Operations
     │                  │
     │                  ├── maxPerTx: 500 USDC
     │                  └── maxPerDay: 2000 USDC
     │
     └── 1% transfer fee → Treasury
```

**DPO2UToken**: ERC-20 with built-in 1% transfer fee. Fee-exempt addresses configurable (LP pools, staking). 100M supply, burnable.

**Treasury**: AccessControl with OPERATOR and GOVERNOR roles. Daily spending limits prevent single-transaction exploits. Accepts ETH and any ERC-20.

**AgentRegistry**: On-chain registry for 6 DPO2U agents. Each agent has a `bytes32` ID, wallet address, permissions bitfield, metadata URI, and ERC-8004 identity NFT ID.

**SwapExecutor**: Automated Uniswap V3 swaps. Converts treasury tokens (e.g., WETH → USDC) for agent operations. Slippage-protected, deadline-enforced.

**DPO2UAgentBridge**: Bidirectional mapping between DPO2U agent IDs and ERC-8004 identity NFTs. Syncs heartbeat, metadata, and reputation.

**ZKComplianceVerifier**: Verifies ZK proofs generated by Midnight's compliance contracts on-chain, enabling cross-chain compliance attestations.

### Compact Layer (Midnight Network)

**AgentRegistry.compact**: Private agent registration with ZK identity. Agents can prove membership without revealing which agent they are.

**PaymentGateway.compact**: Collects service fees with a 40/60 split — 40% to the operating agent, 60% to the shared treasury. Split ratios are governance-adjustable.

**FeeDistributor.compact**: Manages the stake → DUST generation cycle. Agents stake $NIGHT, earn $DUST proportionally, use DUST for operations.

**ComplianceRegistry.compact**: Privacy-preserving compliance attestations. Agents can prove LGPD/GDPR compliance without revealing the underlying data.

**AgentWalletFactory.compact**: Deterministic HD wallet derivation. Each agent gets a unique shielded wallet derived from a master seed.

## Permission Model

```
Bit 0 (1)  = READ      — Query on-chain state
Bit 1 (2)  = WRITE     — Update non-financial state
Bit 2 (4)  = TREASURY  — Withdraw from treasury
Bit 3 (8)  = DEPLOY    — Deploy new contracts
Bit 4 (16) = GOVERNANCE — Change roles and parameters
```

Only `dpo2u-defi-ops` has TREASURY permission (7 = READ+WRITE+TREASURY). This is the only agent that can move funds.

## Deploy Order

```
1. Treasury (standalone, no dependencies)
2. DPO2UToken (needs Treasury address for fee recipient)
3. AgentRegistry (standalone)
4. SwapExecutor (needs Treasury + Token addresses)
5. Grant roles (OPERATOR_ROLE to SwapExecutor on Treasury)
6. Register agents (6 agents with wallets + permissions)
7. Deploy ERC-8004 bridge + register identities
```
